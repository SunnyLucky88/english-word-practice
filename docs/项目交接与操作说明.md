## 文件在哪里修改

| 文件或目录 | 用途及编辑方式 |
| --- | --- |
| `courses.json` | 课程名称、固定地址、首次发布日期、词数、音频目录和描述；`hidden: true` 只隐藏首页卡片，不删除页面 |
| `index.html` | 首页生成结果；通过 `scripts/build-index.cjs` 生成 |
| `lessons/日期-主题.html` | 课程布局、交互、`lesson-content` JSON 词句数据、`AUDIO_BASE`；同时含打包后的课本图和脚本 |
| `assets/日期-主题/images/` | 课本图片源文件；第一、第二单元采用 1080×1527 坐标基准 |
| `assets/日期-主题/book.js` | 页码、图片地址、点读框、朗读顺序和翻页逻辑的源文件 |
| `audio/日期-主题/google-v1/` | 每课原速音频及来源清单；换音新建 `google-v2` 等目录 |
| `scripts/bundle-textbook.cjs` | 把图片与课本脚本打包进课程 HTML；不要只改 HTML 中生成的脚本副本 |
| 外层 `drafts/`、`references/` | 草稿、试听和参考材料，不能整目录复制到发布仓库 |

目前打包脚本和翻页检查脚本**只处理第一、第二单元**。新增第三单元前，需要扩展两份脚本的课程范围；只新增 `courses.json` 条目不会自动启用打包。

## 每次增加课程

1. 明确教材版本、单元、页码范围和是否完整单元。核对书后词表、句子和图片来源。
2. 新课建立独立 HTML、`assets/` 和音频目录；登记 `courses.json`。不覆盖旧课文件。
3. 准备与确认音频，保留来源清单。若指定“先预览”，只制作本地预览，等用户批准发布。
4. 核对点读位置与朗读文本；检查手机宽度、前后翻页、页码切换、播放、停止、倍速和小练习答案隐藏。
5. 执行下节命令；检查改动仅包含本次课程及必要资源。
6. 按授权提交并推送，等待部署成功，再检查公开入口和实际文件。不能把“已推送”当成“已上线”。
7. 手机实际验证应记录设备、浏览器与结果；模拟检查不能写成真机测试通过。

可直接使用的需求模板：

> 制作 2025 年人教 PEP 三年级上册第 X 单元全部内容。词汇按书后词表顺序，句子按教材核对；课本点读、单词点读、句子跟读及中文回想练习都要有。沿用谷歌原速音频和倍速选择，手机自适应。先给预览，确认后再发布。

## 检查与发布命令

在 PowerShell 中进入仓库，逐条执行，任一步报错都应先修复：

```powershell
Set-Location -LiteralPath 'E:\WW\english-word-practice\english-word-practice'
node scripts/bundle-textbook.cjs
node scripts/build-index.cjs
node scripts/check-courses.cjs
node scripts/check-textbook-navigation.cjs
git diff --check
git status --short
```

`check-courses.cjs` 检查目录、词数、引用、来源清单及文件哈希等，不代表发音准确性已逐条人工试听。`check-textbook-navigation.cjs` 模拟缺少 `replaceChildren()` 的旧手机 DOM，检查前后翻页和页码跳转；它不是完整手机浏览器测试。

检查通过且已授权发布后，用明确文件列表提交，避免误带试听和临时工具：

```powershell
git add <本次确认要提交的文件或目录>
git commit -m "描述本次课程或修复"
git push origin main
```

以上尖括号内容是占位说明，执行前须替换。部署后比对页面和新增或变更资源；必要时用 SHA-256 核对线上文件。
